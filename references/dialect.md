# 方言理解表（dialect.md）用法与局限

## 原理

`bridge.py` 启动时会把脚本同目录的 `dialect.md` 内容读出来，追加到 LLM 系统提示末尾：

```
【方言理解规则（来自 dialect.md）】
<文件内容>
```

所以改方言表**不用改代码**，重启桥接服务即生效。

## 能做什么 / 不能做什么

| 目标 | 能否 | 说明 |
|------|------|------|
| 口音普通话 + 方言词 → 听懂 | ✅ | 小米 ASR 抓到近似文字，方言表纠偏 |
| 同音错字 → 还原真意 | ✅ | 表里列"抓错的字→真意"，如"金招"→"今朝" |
| 纯方言整句 → 识别成文字 | ❌ | 卡在小米云端 ASR，改不了（除非刷机拿音频流自建 ASR） |
| 用方言回答 | ❌ | 小米原生 TTS 只念普通话 |

## 表结构

复制 `assets/dialect.example.md` 为脚本同目录 `dialect.md`，按四节填：

1. **词汇对照表**：`| 可能抓成 | 真实意思 |` —— 方言词及常见同音错字 → 普通话
2. **同音纠偏**：从实际 `history.md` 里收集"小爱抓错的句子 → 真实意图"
3. **句式习惯**：方言语序、语气词
4. **测试语料**：主人实际会怎么喊

## 迭代方法

1. 跑一段时间后看 `history.md`（语音原话字段），找 ASR 抓错的地方
2. 把"抓错的原文 → 真实意思"补进同音纠偏表
3. 重启桥接，再实测那几句话
4. 逐步积累，小皮对方言的理解会越来越准

## 若用户有自定义语音识别模型（SKILL）

- 模型装在**电脑端**：电脑版小皮可以直接处理音频，能懂纯方言；音箱端用不上
- 想让音箱也用自建 ASR：唯一路径是刷机拿原始音频流（Open-XiaoAI），再送到自建 ASR —— 需重新评估风险
- 两套并存不冲突：音箱端靠方言表提升理解，电脑端靠 ASR 模型直接听懂
